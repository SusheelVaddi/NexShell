# Pipe Testing Scenarios and Verification Guide

This document outlines practical testing scenarios for verifying command piping (`|`) in **NexShell**. Each scenario includes the command sequence, expected behavior, and an explanation of the underlying kernel mechanics verified by the test.

---

## Overview of Pipe Testing

In NexShell, command pipelines connect the standard output (`STDOUT_FILENO`) of a left child process to the standard input (`STDIN_FILENO`) of a right child process using `pipe()` and `dup2()`. Testing pipelines ensures:
- Data is correctly transmitted across process boundaries via IPC pipes.
- Argument arrays for both left and right commands are properly tokenized.
- Unused pipe file descriptors are closed to enable EOF signaling.
- Process execution failures are isolated without crashing the parent shell.

---

## Test Scenarios

### Scenario 1: Directory Listing Piped to Sort (`ls | sort`)

- **Command**:
  ```bash
  NexShell> ls | sort
  ```

- **Expected Results**:
  The contents of the current working directory are displayed in strict alphabetical order:
  ```text
  README.md
  docs
  main.c
  nexshell
  presentation.html
  ```

- **What This Test Verifies**:
  - **Multi-line Stream IPC**: Verifies that multi-line data generated by `ls` flows completely through `pipe_fd[1]` to `pipe_fd[0]`.
  - **EOF Signalling**: Verifies that `sort` receives an End-of-File (EOF) signal when `ls` completes execution. EOF relies on the parent process and both child processes closing their unused write file descriptors (`close(pipe_fd[1])`). If descriptor closing was omitted, `sort` would hang indefinitely waiting for more input.
  - **Dual Foreground Synchronization**: Verifies that the parent process waits for both child processes (`pid1` and `pid2`) via `waitpid()` before displaying the next shell prompt.

---

### Scenario 2: Echo String Piped to Concatenate (`echo hello | cat`)

- **Command**:
  ```bash
  NexShell> echo hello | cat
  ```

- **Expected Results**:
  ```text
  hello
  ```

- **What This Test Verifies**:
  - **Argument Parsing in Pipelines**: Verifies tokenization of multi-token commands on the left side of a pipe (`echo` + argument `"hello"`).
  - **Single-Line Buffer Transmission**: Confirms that single-line text buffers pass through the pipe without memory corruption, truncation, or appended null characters.
  - **Pass-through Reader Binding**: Confirms that standard stream redirection (`dup2(pipe_fd[0], STDIN_FILENO)`) enables utility processes like `cat` to read directly from kernel pipe buffers.

---

### Scenario 3: Working Directory Piped to Concatenate (`pwd | cat`)

- **Command**:
  ```bash
  NexShell> pwd | cat
  ```

- **Expected Results**:
  Displays the absolute directory path of the current working directory (e.g.):
  ```text
  /home/user/NexShell
  ```

- **What This Test Verifies**:
  - **Environment-Dependent Output Handling**: Verifies that commands relying on environment parameters (`pwd` querying process working directory) correctly write their output into the pipe stream.
  - **System Binary Pipeline Execution**: Confirms seamless execution when pipe components involve built-in path resolution via `execvp()`.

---

### Scenario 4: Invalid Command Piped to Concatenate (`invalid command | cat` / `non_existent_cmd | cat`)

- **Command**:
  ```bash
  NexShell> non_existent_cmd | cat
  ```

- **Expected Results**:
  An error message is printed to standard error by the left child process:
  ```text
  execvp failed: No such file or directory
  ```
  `cat` receives an immediate EOF (0 bytes read) because the left child exits immediately upon `execvp` failure. No output is produced by `cat`, and NexShell redisplays the prompt cleanly without crashing or hanging:
  ```text
  NexShell> 
  ```

- **What This Test Verifies**:
  - **Error Isolation**: Verifies that an execution failure (`execvp` returning `< 0`) inside one pipe child does not crash or corrupt the parent shell process.
  - **Graceful Failure Handling**: Ensures that when `execvp` fails in the left process, the child invokes `exit(1)`, automatically closing its pipe file descriptors and allowing downstream processes (`cat`) to terminate gracefully.
  - **Parent Shell Resilience**: Confirms that the parent process cleans up descriptors and handles process termination statuses cleanly.

| Scenario | Command | Expected Output | Critical Mechanism Verified |
| :--- | :--- | :--- | :--- |
