NexShell — Simplified Unix Shell in C

College Hackathon Project — Operating Systems & Systems Programming

🎯 Problem Statement & Objective

Building a custom, light-weight Unix-like command interpreter in C to explore Linux process creation, inter-process communication, and I/O redirection.

  • Platform: Linux / WSL (Ubuntu) compiled with GCC
  • Demonstrate real low-level POSIX system calls
  • Implement a robust Read-Eval-Print Loop (REPL)

⚙️ Core POSIX System Calls

  • fork() — Duplicates caller into a new child process
  • execvp() — Replaces child image with target binary
  • waitpid() — Synchronizes parent with child (or WNOHANG)

🔀 File Descriptor Manipulation

  • pipe() — Created before child processes to form data channel
  • dup2() — Overwrites standard input (0) or output (1)
  • chdir() — Changes shell directory inside parent process

Demo Commands

Tested Live Execution Sequence

nexshell — bash
NexShell> pwd NexShell> ls NexShell> mkdir demo NexShell> cd demo NexShell> pwd NexShell> cd .. NexShell> ls > files.txt NexShell> cat < files.txt NexShell> ls | grep test NexShell> sleep 10 & NexShell> pwd NexShell> exit

💡 Key Captions & Behavior

  • Built-ins (cd / exit): Executed in the parent process using chdir().
  • Redirection (> / <): Uses open() and dup2() to route command input/output.
  • Command Pipes (|): Allocates pipe() before spawning children connected via stream descriptors.
  • Background Execution (&): Strips &, forks asynchronously, and returns the NexShell> prompt immediately.
Slide 05 // Summary 05 / 05

Challenges & Future Scope

Engineering Lessons & Next Technical Milestones

🛠️ Key Technical Challenges

  • FD Leak Prevention: Ensuring both parent and children close unused pipe ends.
  • Zombie Management: Implementing non-blocking waitpid(-1, NULL, WNOHANG) reaping.
  • Parent Environment: Executing cd in parent via chdir() rather than a child process.

🚀 Future Technical Scope

  • Multi-stage pipeline chaining (cmd1 | cmd2 | cmd3)
  • Combining redirection with pipes (cat in.txt | grep err > out.txt)
  • Full Job Control (jobs, fg, bg, Ctrl+C, Ctrl+Z)
  • Command history and readline tab auto-completion
